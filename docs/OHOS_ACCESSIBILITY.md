# 网页系统无障碍接入

## 状态

2026-10-07：第一版实现草稿，尚未在 CI 编译或真机验收，不应标记为已支持或已完成。

本地仅进行了非编译检查：新文件空白检查、公开 NDK 头文件的符号声明核对、Chromium 154 枚举核对、`chrome/browser/BUILD.gn` 的主补丁及当前增量补丁顺序应用验证，以及测试页 JavaScript 语法检查，均通过。公开 NDK 头文件核对不能替代 runner 实际 SDK 的编译检查。

## 当前路径

- XComponent 的原生 Surface 创建时获取 `ArkUI_AccessibilityProvider`，注册 API 15 的带实例标识回调；Surface 销毁时删除注册记录。使用现有 XComponent 所属 provider，不自行释放系统持有的对象。
- 系统首次查询后，浏览器 UI 线程为当前网页启用 scoped accessibility mode。通过 Chromium 154 的 `BrowserAccessibilityManager` 和平台遍历接口获取节点，因此可沿跨框架树边界遍历，不要求渲染器与浏览器同进程。
- 系统回调只读取独立数据快照。网页对象及树节点不跨线程传递；操作异步返回 Chromium UI 线程，重新校验 provider 代次、活动标签页、主框架树及目标节点。
- 页面事件标记快照需要刷新，现有浏览器轮询约每 200 ms 合并更新；不在无障碍未被查询时遍历网页树。
- 用实例代次拒绝旧 Surface 回调；用快照所有者区分标签页，防止后台旧标签页销毁时清空新标签页的数据。隐藏、导航及销毁时清理属于该页面的快照。
- 导出名称、角色、描述、边界、可用性、选中状态、输入焦点及子节点；支持顺序焦点查找、点击、设置文本、无障碍焦点和前后滚动。密码值不进入快照，不增加网页文本或网址日志。
- 系统 provider 会叠加 XComponent 的宿主偏移，快照先从 Chromium 屏幕物理像素坐标减去原生 Surface 原点，避免重复偏移。

新增上游构建改动位于 `patches/ohos-web-accessibility.patch`，已在 `scripts/ci-incremental-build.sh` 登记。补丁对 `chrome/browser/BUILD.gn` 只有一个修改段。新增源码通过 overlay 同步，构建只在 CI 进行。

## 验收步骤

测试前先检查真机当前前台是否正在使用其他应用，协调好测试时机再操作。先执行 `scripts/serve-test-pages.sh`，按现有设备转发方式打开 `docs/test-pages/accessibility.html`。

| 场景 | 预期 |
| --- | --- |
| 文本、链接、按钮、输入框 | 读屏能报出名称和合适的角色；双击可操作；输入框可编辑 |
| 勾选框、单选框、禁用按钮 | 正确读取状态，禁用按钮不能被激活 |
| 密码输入 | 不把密码原文作为节点内容或写入日志 |
| 隐藏内容 | 不出现在可访问节点遍历中 |
| 动态插入及删除 | 新节点可找到，已删除节点不能继续被操作 |
| 内部滚动及页面滚动 | 操作对应滚动容器；节点边界更新，不错误点击旧位置 |
| 框架 | srcdoc 基础测试通过；再用不同站点验证跨进程 iframe，不串节点 ID |
| 焦点 | 前进、后退与视觉顺序一致；输入焦点和无障碍焦点分开；读屏框与控件位置一致 |
| 标签页、无痕窗口 | 切换后只暴露当前页面；关闭后台标签页不清空前台页面 |
| 导航、前进后退、渲染器退出 | 不返回失效节点，不崩溃；新文档可重新查询 |
| 旋转、折叠、窗口移动和 Surface 重建 | 屏幕坐标正确，旧实例回调无效，新实例可以重新建立树 |
| 手机单进程 | `--single-process` 下完成全部基础操作 |
| 平板/PC 多进程 | 完成相同操作并验证跨站框架 |

## 尚需验证或补齐的范围

- CI 中 runner 实际 SDK 的头文件、链接库及 Chromium GN 依赖。
- 系统读屏首次查询、触摸探索和焦点高亮的实际协议行为；组件内坐标转换仍需真机核对窗口偏移和缩放。
- 当前焦点导航实现前进/后退，不包含二维方向的几何导航。
- 当前角色映射覆盖基本控件；表格、列表层级、标题级别、滑块范围、混合勾选状态的完整系统语义尚未补齐。
- 文本选择、光标设置和 HTML 项目导航等动作尚未实现；只导出已支持的动作。
- 内容变动发送页面内容更新事件，尚未专门实现 aria-live 的公告策略。
- 目前首次查询后，无障碍模式保持到页面销毁；系统读屏关闭后的停用通知和资源释放策略仍需接入。
- 本页测试不覆盖外壳弹窗及所有 Chromium Views 控件；辅助窗口的无障碍树需要单独核对。
